# BSMS UX Design Principles

**Direction (per your instruction, 2026-09-12): clean, modern, enterprise-grade.** This governs the Next.js web app's visual language. It's a separate axis from `KEYBOARD_SHORTCUTS.md`'s Tally-inspired interaction model — that doc borrows Tally's keyboard speed, not its look; this doc is what actually gets rendered.

## What "enterprise-grade" means here, concretely
Not generic-corporate or dated ("enterprise software" often implies cluttered/dense/dull) — closer to the current bar set by tools like Linear, Stripe Dashboard, or Notion: confident typography, restrained color, clear information hierarchy, and enough whitespace that dense data (invoice line items, inventory tables, GST reports) still reads calmly rather than as a wall of numbers.

## Concrete choices to carry into implementation
- **Component library**: a modern headless/unstyled base (e.g. shadcn/ui on top of Radix primitives + Tailwind) rather than a heavier prebuilt kit (MUI, Ant) whose default look reads as generic — this was flagged as an open question in `WEB_APP_PLAN.md`, resolving it here in favor of the direction that gives full visual control. (Note: the shadcn version actually installed uses Base UI primitives, not Radix — same idea, different underlying library; see `render`-prop usage notes in the codebase.)
- **Typography**: **Plus Jakarta Sans** (not Inter — picked during the design-canvas review, 2026-09-12, to read as more distinctive than the "default enterprise sans" everyone uses) with a clear, limited type scale so headers, table data, and metadata are visually distinct at a glance.
- **Color**: **"Warm Enterprise" direction, finalized 2026-09-12** — a dark charcoal sidebar (`oklch(0.2 0.015 260)`) with a warm amber/orange primary accent (`oklch(0.72 0.17 55)`) against a warm off-white content background (`oklch(0.98 0.004 90)`). Chosen from a 6-direction design-canvas review (Warm Enterprise, Cool Corporate/indigo, Minimal/monochrome, Bold Automotive/red, Editorial Premium/serif-cream, Top-Nav SaaS/teal) — see the picked canvas at `claude.ai/code/artifact/899b956b-2c1e-4635-8d00-e0951e1cf473`. All tokens live in `apps/web/src/app/globals.css`; semantic status colors (`--success`, `--warning`, `--info` + soft variants) were added there specifically for ServiceTicket/DelegationTask status badges — see `apps/web/src/components/status-badge.tsx`, the shared `StatusBadge` component this doc's badge-system line below called for and that now actually exists.
- **Density with breathing room**: data-heavy screens (inventory, invoices, reports) use generous row height and clear column alignment rather than cramming to fit more per screen — the "enterprise" failure mode to avoid is optimizing for density over legibility.
- **Motion**: subtle only — a fast fade/slide on modals and route transitions, no decorative animation. Reinforces "confident," not "playful."
- **Empty/first-run states**: since a non-technical owner is using this (`INSTALLATION_UX.md`), empty states (no inventory yet, no tickets yet) need a clear next action, not just a blank table — this is where "enterprise-grade" and "non-technical-friendly" reinforce each other rather than conflict.
- **Dark mode**: not required for v1, but worth architecting the token/theming approach (CSS variables, not hardcoded colors) so it's a later addition rather than a rewrite.

## How this interacts with other decisions already made
- **Keyboard-shortcut affordances** (`KEYBOARD_SHORTCUTS.md`) need to look like a deliberate, modern feature (subtle key-badge chips, a polished command palette like Linear's `Cmd+K`) — not like Tally's boxy always-on button bar. Same underlying behavior, modern skin.
- **Setup wizard / plain-language UX** (`INSTALLATION_UX.md`) is itself a design surface, not just copywriting — a clean multi-step wizard with a progress indicator is part of "enterprise-grade," not separate from it.
- **PDF invoices/estimates** (open question in `WEB_APP_PLAN.md`: server- vs client-generated) should carry the same visual restraint — a clean, well-typeset invoice, not a dense default-template look — regardless of which generation approach is chosen.
